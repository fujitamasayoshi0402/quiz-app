# ADR-0030: 所属している人が、自分でテナントから退会できるようにする。退会すると、そのテナントでの回答の履歴を消す

- ステータス: Accepted
- 決定日: 2026-10-15

## 背景と課題

テナントに入る道は 3 つある（招待、公開テナントへの参加、自分で作る。[ADR-0025](0025-let-signed-in-users-join-public-tenants.md)、[ADR-0028](0028-let-signed-in-users-create-their-own-tenant.md)）。
抜ける道はない。試しに公開テナントに参加した人も、招待を受けた人も、所属の一覧に残り続ける。

所属している人が、自分で抜けられるようにする。決めること。

- **誰が退会できるか。** 管理者も抜けられるか。最後の管理者が抜けると、管理者のいないテナントが残る
- **共有のデモのアカウント。** パスワードを公開しており、誰でも操作できる（[ADR-0029](0029-let-visitors-sign-in-as-shared-demo-account-without-login-screen.md)）
- **回答の履歴をどうするか。** 残すか、消すか
- **もう一度入るとき**の扱い
- **API の置き場所。** テナント配下か、テナントの外（`/api/me`）か

## 判断基準

- **退会した人の記録を、本人の意思に沿って扱うこと。** 抜けたテナントに、自分の成績を残したくない人がいる
- テナントを使えない状態（管理者のいないテナント）にしないこと
- テナントの境界を広げないこと（開発ガイドライン「API の URL」）
- 作る量を抑える

## 検討した選択肢

### 回答の履歴

#### A. 消す

退会するときに、そのテナントでの挑戦（出題と回答を含む）と、ランキングへの参加を消す。

- 利点: 抜けたテナントに、自分の記録が残らない。ランキングの集計からも外れる
- 欠点: 消したものは戻らない。もう一度入っても、前の成績は引き継げない

#### B. 残す

所属だけを外し、履歴は残す。ランキングは、いまも所属している人だけを載せている（`TenantMembers`）ため、表には出ない。

- 利点: 戻ったときに成績を引き継げる。誤って抜けても失わない
- 欠点: 抜けたテナントに記録が残り続ける。本人からは見えないのに、消す手段がない

### 共有のデモのアカウント

#### A. 退会できない

- 利点: 誰かが抜けても、見に来たほかの人がデモのテナントに入れなくなることがない
- 欠点: 共有のアカウントで公開テナントに参加すると、抜けられない

#### B. 退会できる

- 欠点: 1 人が押すと、パスワードを知る全員がデモのテナントに入れなくなる。運用者が所属を戻すまで続く

### API の置き場所

#### A. テナント配下の play（`DELETE /api/t/{slug}/play/membership`）

- 利点: 所属していることは、パスの規約で確かめられる。テナントの境界のテストの対象に入る
- 欠点: 特になし。管理者も play を呼べる

#### B. テナントの外（`DELETE /api/me/tenants/{slug}`）

- 欠点: テナントの外の API が増える。所属の確かめと、テナントの設定（RLS）を自分で書くことになる

## 決定

**履歴は A（消す）、共有のアカウントは A（退会できない）、API は A（テナント配下の play）を採用する。**

| 項目 | 決めたこと |
| --- | --- |
| 退会できる人 | 所属している人。一般ユーザーも管理者も |
| 最後の管理者 | 退会できない。ほかの人を管理者として招待してから抜ける。自分で作ったテナントも同じ（テナントを消す機能はない） |
| 共有のアカウント | どのテナントからも退会できない |
| 回答の履歴 | そのテナントでの挑戦（出題と回答）と、ランキングへの参加を消す。ほかのテナントでの履歴は残す |
| 所属 | 論理削除する（`core.tenant_members.deleted_at`） |
| もう一度入る | 公開テナントは一覧から参加できる。非公開のテナントは招待し直す。新しい所属として入り、履歴は空から始まる |

- **共有のアカウントは、デモのテナントに限らず退会できない。** どのテナントがデモかは、シードのデータであってアプリの仕様ではない（開発ガイドライン「シードデータ」）。共有のアカウントの印（`core.users.shared`、ADR-0028）だけで決める
- 所属を外すことと履歴を消すことは、同じトランザクションで行う。片方だけが残らない
- 最後の管理者かどうかは、テナントの行を `FOR UPDATE` で押さえてから数える。管理者が 2 人で同時に抜けて、0 人になることを防ぐ
- 履歴を消すのは answer のモジュールで、テナントのモジュールは呼ぶ側が持つインターフェース（`MemberAnswerHistory`）越しに頼む。テナントのモジュールは answer の表に触れない（[ADR-0023](0023-keep-answer-as-module-in-quiz-service.md) と同じ分け方）
- 退会できないときは 409 と理由（`last_admin` / `shared_account`）を返す。画面が案内を変える

### ADR-0007 との関係

[ADR-0007](0007-soft-delete-master-data.md) は、マスタデータ（カテゴリ・難易度・クイズ）を論理削除し、回答の履歴が意味を保つようにした。
回答の履歴そのものは対象外で、この ADR はそれを物理削除する。マスタデータの扱いは変えない。

## 結果

### 良い影響

- 試しに参加したテナントから、自分で抜けられる。抜けたテナントに記録が残らない
- 管理者のいないテナントは生まれない

### 悪い影響・受け入れるリスク

- **退会は取り消せない。** 消した履歴は、バックアップから戻す（Runbook）以外に戻す手段がない
- 最後の管理者は、ほかの人を招待するまで抜けられない。自分で作ったテナントからは、実質的に抜けられない
- 共有のアカウントで参加した公開テナントからは、抜けられない

### 緩和策

- 画面で、履歴が消えることを示し、確かめてから退会する（DEV-157）
- 退会できない人には、押す前に理由を示す

## 検証事項

- 消すのは、そのテナントでの本人の履歴だけで、ほかの人の履歴と、ほかのテナントでの本人の履歴は残る（`TenantLeavingApiTest`）
- 最後の管理者と共有のアカウントは退会できない（`TenantLeavingApiTest`）
- 別のテナントのデータは変わらない（`TenantBoundaryApiTest`）
