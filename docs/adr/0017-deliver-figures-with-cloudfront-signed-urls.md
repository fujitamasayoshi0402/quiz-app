# ADR-0017: 解説図は非公開の S3 に置き、API が出す CloudFront の署名付き URL で配る

- ステータス: Accepted
- 決定日: 2026-09-26

## 背景と課題

Phase 4 で、クイズの解説に図を付ける。図は draw.io で描き、原本（`.drawio`）と、書き出した SVG を持つ。
管理画面への draw.io の埋め込み（DEV-69）と、利用者の画面での表示（DEV-70）の前に、
図をどこに置き、どう配るかを決める（DEV-62）。

守らなければならないこと。

- **テナントの図は、そのテナントの利用者にだけ見せる。** 別テナントの図や、ログインしていない相手には返さない
- **出題の時点（回答する前）には、図も見せない。** 出題の API が解説と正解を返さない不変条件は、図にも当てはまる
- **SVG はスクリプトを含められる。** 管理者が置いた SVG を、アプリのオリジンで開かせない。
  開かせると、SVG の中のスクリプトが利用者のセッションで API を呼べる

あわせて、次も決める。

- 原本と SVG の対応と、図を差し替えたときのキャッシュの扱い
- 待機中の費用。CloudFront を置くなら、web を配る Amplify（[ADR-0012](0012-serve-frontend-on-amplify-hosting.md)）との役割の分け方

## 判断基準

- 誰に見せるかを、今の認可の仕組み（所属とロール、[ADR-0016](0016-authenticate-with-cognito-managed-login.md)）で決められること。図のために別の認可を作らない
- SVG を、アプリと別のオリジンから配れること。スクリプトを動かさない応答ヘッダを付けられること
- URL が漏れても、見られる時間が短いこと
- 待機中の費用がほぼかからないこと
- バケットを公開しないこと

## 検討した選択肢

どの案でも、図は非公開の S3 に置く。違うのは、利用者のブラウザまでの経路。

### A: API が CloudFront の署名付き URL を出す

画面は `<img src="/api/t/{slug}/play/figures/{id}">` を読む。
quiz-service が所属と図の存在を確かめ、期限の短い CloudFront の署名付き URL へ 302 で送る。
CloudFront は署名を確かめ、OAC（Origin Access Control）で S3 から読む。

- 誰に見せるかは、今の API の認可がそのまま決める。CloudFront は署名を確かめるだけ
- 図のドメインがアプリと分かれる。応答ヘッダのポリシーで、CSP（`sandbox`）と `nosniff` を付けられる
- 図はエッジでキャッシュされる。2 回目からは S3 に届かない
- **署名の鍵の組を管理する。** 秘密鍵を quiz-service に渡し、公開鍵を CloudFront のキーグループに登録する
- CloudFront はローカルにない。ローカルでは別の方法で URL を作る

### B: API が S3 の署名付き URL を出す

A の CloudFront を S3 の署名付き URL に置き換える。quiz-service はタスクのロールで署名する。

- 鍵を持たずに済む。ローカル（LocalStack）と AWS で実装が 1 つになる
- バケットのドメインはアプリと別のオリジンなので、SVG のスクリプトが動いても、アプリの Cookie には届かない
- **応答ヘッダを付けられない。** S3 のオブジェクトに付けられるのは `Content-Type` や `Cache-Control` などに限られ、CSP は付けられない
- エッジでキャッシュされない

### C: API が S3 から読んで、そのまま返す

- インフラは S3 だけで済む。認可は今の API のまま
- **SVG をアプリと同じオリジンから配る。** CSP の `sandbox` を付け忘れると、そのまま XSS になる
- 図を読むたびに、web の proxy（Amplify の SSR）、ALB、quiz-service を通る

### D: 推測できないキーで公開する

- 最も単純。署名も認可も要らない
- **URL が漏れると、期限なく誰でも見られる。** ログインしていない相手に返さない、という条件を満たせない

### E: CloudFront の署名付き Cookie

A の署名を URL ではなく Cookie で渡す。テナントの図をまとめて許せる。

- Cookie を図のドメインに届けるには、アプリと図のドメインが親ドメインを共有し、web がその Cookie を発行する必要がある
- ローカル（`localhost`）では同じ形を再現できない

## 決定

**A を採用する。**

B は鍵の管理が要らないぶん速く作れるが、SVG に付けられる守りが別のオリジンだけになる。
C は SVG をアプリのオリジンに置くため、ヘッダ 1 つの付け忘れが XSS になる。
D は条件を満たさない。E は Cookie の配り方が構成を縛る。

```
管理者 → web の proxy → quiz-service ─┬→ S3（原本と SVG を置く）
                                      └→ quiz.figures（図の行。テナントの行レベルセキュリティ）

利用者 → <img src="/api/t/{slug}/play/figures/{id}">
       → web の proxy → quiz-service（所属と図の行を確かめる）→ 302（署名付き URL）
       → CloudFront（署名を確かめ、応答ヘッダを付ける）→ OAC → S3
```

### 1. 置き場所

- バケットは非公開（ブロックパブリックアクセス）で、SSE-S3 で暗号化する。HTTPS 以外の要求は拒否する
- **キーにテナントを含める。** SVG は `svg/{テナントの ID}/{図の ID}.svg`、原本は `drawio/{テナントの ID}/{図の ID}.drawio`
- 図は `quiz.figures` に行を持つ。`tenant_id` と行レベルセキュリティを付け、ほかのテーブルと同じく DB でも分ける
- **テナントは要求のテナントから決め、図の ID だけを受け取る。** 別テナントの図の ID を指定しても、行が見えず 404 になる。
  行の確かめを通り抜けても、キーが自テナントの下を指すため、別テナントの図には届かない
- CloudFront が読めるのは `svg/` の下だけ。原本は quiz-service だけが読み書きし、管理者に API で返す

### 2. 配信

- CloudFront の独自ドメイン（`figures.dev.<ドメイン>`）で配る。TLS 1.2 以上に絞るため。
  CloudFront の既定のドメイン（`*.cloudfront.net`）では、最低のバージョンを選べない。証明書は us-east-1 の ACM に置く
- 署名付き URL は、固定のポリシー（canned policy）で作る。**期限は 5〜10 分。**
  5 分の区切りの終わりから 5 分後を期限にし、同じ区切りの間は同じ URL を返す。ブラウザのキャッシュが効く
- 302 の応答は `Cache-Control: private` で、1 分だけブラウザに持たせる。Amplify の CDN に共有させない
- 応答ヘッダのポリシーで、次を付ける
  - `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'; img-src data:; font-src data:; sandbox`。
    SVG を直接開いても、スクリプトは動かず、外へ通信もしない。`<img>` で読むときは、もともとスクリプトは動かない
  - `X-Content-Type-Options: nosniff`、`Strict-Transport-Security`、`Referrer-Policy: no-referrer`
- Amplify は web を配り、図は配らない。Amplify の CDN は Amplify が管理しており、非公開の S3 と署名を組み込めない。
  図を別の CloudFront にすることで、オリジンも分かれる

### 3. 図は書き換えない

- **図は一度置いたら変えない。** 描き直した図は、新しい ID の図として置く。キャッシュを無効にする操作が要らない
- S3 のオブジェクトは 1 年のキャッシュを許す（`immutable`）。CloudFront のキャッシュは、クエリ文字列（署名）をキーに含めない
- 消すときは、行と S3 のオブジェクトを消す（論理削除にしない）。発行済みの署名付き URL は、期限（最長 10 分）まで有効
- 図の ID は、推測できない乱数（UUID v4）。**図の ID を出題の応答に含めない**（DEV-70）。出題の時点で見られないことは、ID を渡さないことで守る

### 4. SVG の受け付け

- **無害化はしない。** draw.io の SVG は、HTML のラベルを `foreignObject` で持つ。要素を削ると表示が崩れる。
  スクリプトは、別のオリジンと CSP で動かさない
- 受け付けるのは、整形式の XML で、ルートが SVG の名前空間の `svg` 要素のものだけ
- 確かめるときに DTD を読まない。外部の DTD を取りに行かず、DOCTYPE の中で宣言した実体も展開しない（XXE と展開の爆発を防ぐ）。
  draw.io は SVG に DOCTYPE を付けて書き出すため、DOCTYPE があること自体は拒まない
- SVG と原本は、それぞれ 1 MB まで

### 5. 鍵

- 鍵の組（RSA 2048）は Terraform が作る。公開鍵を CloudFront のキーグループに、秘密鍵を SSM Parameter Store（SecureString）に置く
- quiz-service のタスクには、ECS の `secrets` で秘密鍵を渡す。読めるのはアプリのタスクの実行ロールだけで、マイグレーションのタスクには渡さない
- Secrets Manager ではなく Parameter Store にしたのは、自動のローテーションを使わないため。標準のパラメータは料金がかからない
- 入れ替えるときは、新しい公開鍵をキーグループに足し、アプリを新しい鍵に替えてから、古い公開鍵を外す。発行済みの URL は最長 10 分で切れる

### 6. ローカル

- 置き場所は LocalStack の S3。URL は LocalStack の署名付き URL にする（B の方式）
- 図の置き場所と、URL の作り方はインターフェースで分ける。AWS かどうかは設定で決め、プロファイルでは分けない（dev は AWS でも使う）

## 結果

### 良い影響

- 図を誰に見せるかは、API の認可が 1 か所で決める。CloudFront には署名を確かめることしか任せない
- SVG はアプリと別のオリジンから、スクリプトを止めるヘッダ付きで配られる
- 図を差し替えてもキャッシュを無効にしなくてよい
- 待機中の費用はほぼかからない。CloudFront は月 1 TB と 1,000 万リクエストまで無料枠に収まり、Parameter Store の標準のパラメータと ACM の証明書は無料。S3 は置いた量だけ

### 悪い影響・受け入れるリスク

- **秘密鍵が Terraform の state に入る。** state のバケットは非公開で暗号化しており、ほかの秘密（Cookie の暗号鍵など）と同じ扱いになる
- ローカルでは CloudFront を通らない。応答ヘッダと署名の検証は、dev に載せて初めて確かめられる
- 図の表示に、API への 1 往復（302）が挟まる
- 発行した URL は、期限までは誰でも使える（最長 10 分）
- LocalStack は再起動で中身が消える。ローカルの図は、DB の行だけが残る

### 緩和策

- デプロイの後のスモークテストで、図を置き、署名付き URL から CSP の付いた SVG が返ることを確かめる
- CloudFront の署名は API テストで、URL の形（ドメイン、キー、期限）を確かめる。署名そのものは SDK に任せる
