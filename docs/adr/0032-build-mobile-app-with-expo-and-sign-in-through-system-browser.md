# ADR-0032: モバイルアプリは Expo の managed で作り、ログインはシステムのブラウザで Managed Login を開く。API は直接呼ぶ

- ステータス: Accepted
- 決定日: 2026-10-16

## 背景と課題

一般ユーザー向けのアプリを React Native で作る（ロードマップの Phase 8）。API は今のものをそのまま使う。
画面のほかに、後から変えにくいことがある。

- **作り方。** Expo に任せるか、ネイティブのプロジェクトまで自分で持つか
- **ログイン。** web は、web のサーバーがトークンを受け取って暗号化した Cookie に置き、ブラウザには渡さない（[ADR-0016](0016-authenticate-with-cognito-managed-login.md)）。
  アプリには web のサーバーがなく、トークンを端末に置くことになる
- **パスキー。** RP ID は Cognito のプレフィックスドメイン。web で登録したパスキーをアプリでも使えるか
- **API の呼び方。** web の proxy を通すか、API Gateway を直接呼ぶか
- **web との共有。** 生成した API クライアント、解説の Markdown の表示（生の HTML を通さない。[ADR-0018](0018-write-explanations-in-markdown-and-render-on-screen.md)）
- **配り方と費用。** ストアに出すには、年額と審査が要る

## 判断基準

- バックエンドが確かめるのは、いまと同じ Cognito のアクセストークンだけにする。認証の経路を増やさない
- アプリに秘密を持たせない。アプリの中身は、取り出して読めるものとして扱う
- web と同じ規則（生の HTML を通さない、画像は `figure:` の図だけ）を、同じ仕組みで守る
- 費用を増やさない（予算は月 30 ドル。開発ガイドライン「コスト方針」）。ストアの年額は、公開すると決めたときに払う

## 検討した選択肢

### 作り方

#### A. Expo の managed ワークフローと EAS Build

ネイティブのプロジェクト（`ios/`、`android/`）を持たず、Expo の設定（`app.config.ts`）から作る。ビルドは EAS（クラウド）か手元で行う。

- 利点: ネイティブのコードを書かずに進められる。TypeScript と、web の生成の仕組みを使い回せる。EAS の無料の枠（月に iOS 15 回・Android 15 回）で足りる
- 欠点: ネイティブの部分は Expo が隠すので、iOS と Android の仕組みへの理解は深まらない。Expo にないネイティブの機能が要ると、作り方を変えることになる

#### B. prebuild でネイティブのプロジェクトを持つ

- 利点: Associated Domains などを自分で設定でき、仕組みが分かる
- 欠点: Xcode と Android Studio の環境を持ち、Expo の版を上げるたびにネイティブの差分を直す。時間は倍ほどかかる

### ログイン

#### A. システムのブラウザで Managed Login を開き、PKCE でコードを受ける

`expo-auth-session` で、OS のブラウザの画面（iOS の `ASWebAuthenticationSession`、Android の Custom Tabs）に Managed Login を開く。
戻り先はアプリのスキーム（`quizapp://auth/callback`）。シークレットを持たない、アプリ用のクライアントを Cognito に足す。

- 利点: ログインの画面と、パスワード・パスキー・パスワードの再設定は、web と同じものを使う。アプリはパスワードに触れない（RFC 8252 の推奨する形）
- 欠点: アプリ用のクライアントが増え、バックエンドが受け付ける `client_id` が 2 つになる

#### B. アプリの画面でパスワードを受け、`InitiateAuth` を呼ぶ

- 利点: 画面を自由に作れる
- 欠点: アプリがパスワードに触れる。パスキーとパスワードの再設定を、アプリで作り直すことになる。クライアントが API でのパスワードの認証を許すため、Managed Login を通らない入口が増える

#### C. web のクライアントを使い回す

- 利点: Cognito の設定を変えない
- 欠点: web のクライアントはシークレットを持つ。アプリに入れると、秘密ではなくなる

### パスキー

#### A. システムのブラウザの中で使う

Managed Login はブラウザの画面で開くので、WebAuthn はブラウザが扱う。web で登録したパスキー（iCloud キーチェーンや Google パスワード マネージャーで同期したもの）が、そのまま使える。

- 利点: 作るものがない。RP ID も変わらない
- 欠点: ログインのたびに、ブラウザの画面が一度開く

#### B. OS のパスキーの API を、アプリから直接呼ぶ

- 利点: ブラウザの画面を開かずに済む
- 欠点: **RP ID のドメインに、アプリを結び付けるファイル（`apple-app-site-association`、`assetlinks.json`）を置く必要がある。** RP ID は Cognito のプレフィックスドメインで、こちらからファイルを置けない。
  独自ドメインに替えると RP ID が変わり、登録済みのパスキーが使えなくなる。ネイティブの設定が要り、作り方の A とも合わない

### API の呼び方

#### A. API Gateway を直接呼び、`Authorization` にアクセストークンを付ける

- 利点: スモークテストと同じ経路で、バックエンドは変わらない。CORS も要らない（ブラウザではない）
- 欠点: web の proxy がしていること（トークンの更新、`traceparent` を作る）を、アプリが自分でする

#### B. web の proxy を通す

- 利点: proxy の仕組みを使える
- 欠点: proxy はセッションを Cookie で持つ。アプリのために Cookie を扱うか、別の入口を作ることになる。Amplify の SSR を経由する分、遅く、費用もかかる

### 解説の Markdown

#### A. web と同じパーサ（remark と GFM、改行）で構文木にし、React Native の部品に自分で写す

- 利点: 解析の結果が web と同じになる。写す先を自分で決めるので、HTML の節は文字として出し、画像は `figure:` だけを出す、という規則を写す側に書ける
- 欠点: 見出し、表、コードなど、節の種類ごとに部品を書く

#### B. React Native の Markdown のライブラリを使う

- 利点: 書く量が少ない
- 欠点: パーサが web と違い、同じ解説の見え方が分かれる。HTML や画像の扱いを、ライブラリの設定に頼る

#### C. WebView で web の部品をそのまま出す

- 利点: 見え方は web と同じ
- 欠点: WebView の中で HTML を描くことになり、ADR-0018 が避けた形に近づく。図を取る認証も WebView に渡す

## 決定

**作り方は A（Expo の managed）、ログインは A（システムのブラウザ、PKCE）、パスキーは A（ブラウザの中で使う）、API は A（直接呼ぶ）、Markdown は A（同じパーサで構文木にして写す）を採用する。**

| 項目 | 決めたこと |
| --- | --- |
| 置き場所 | `apps/mobile`。pnpm のワークスペースに足す。一般ユーザーの画面だけを作り、管理の画面は作らない |
| Cognito のクライアント | アプリ用に 1 つ足す。シークレットを持たず、OAuth のコードのフローだけを許す（API でのパスワードの認証は許さない）。スコープは web と同じ |
| 戻り先 | `quizapp://auth/callback`。Expo Go で試すときだけ、シミュレータの `exp://127.0.0.1:8081/--/auth/callback` も許す |
| PKCE | 毎回付ける。カスタムスキームは別のアプリにも登録できるため、コードを横取りされても、verifier がなければトークンにできない |
| トークン | アクセストークンとリフレッシュトークンを `expo-secure-store`（iOS のキーチェーン、Android の Keystore）に置く。期限が近ければ、API を呼ぶ前にリフレッシュトークンで更新する |
| ログアウト | リフレッシュトークンを失効させ（`/oauth2/revoke`）、Managed Login のログアウトも開く。開かないと、ブラウザに残った Cognito のセッションで、次のログインが自動で通る |
| バックエンド | 受け付ける `client_id` を、web とアプリの 2 つにする。ほかは変えない |
| API | API Gateway（`api.dev.<ドメイン>`）を直接呼ぶ。接続先はビルドのときに渡す。web の proxy は通さない |
| API クライアント | web と同じ定義（`docs/api/openapi.yaml`）から、アプリの中に orval で生成する。応答は Zod で確かめる。呼び方（接続先、トークン）が web と違うため、生成物は共有しない |
| 解説 | remark（GFM、改行）で構文木にし、React Native の部品に写す。HTML の節は文字として出し、画像は `figure:` の図だけを出す。web の `markdown.test.tsx` と同じ性質をテストで固定する |
| 解説図 | `/play/figures/{id}/preview` をトークンを付けて呼び、署名付き URL へのリダイレクトをたどる。押すと、図か PDF を開く |
| デモ | アプリには「デモとして入る」を置かない。web の入口は、web のサーバーがパスワードを持つ（[ADR-0029](0029-let-visitors-sign-in-as-shared-demo-account-without-login-screen.md)）。アプリに置くと、公開のアプリにパスワードと、API でのパスワードの認証を入れることになる。共有のデモのアカウントは、Managed Login に打ち込めば使える |
| 配り方 | シミュレータ、Expo Go、開発用のビルド（Android の実機は APK）まで。ストアへの公開は、prod を公開するときに決める（下の「ストアに出すとき」） |

### ストアに出すとき

いまは出さない。出すと決めたときに必要になるもの（決定日の時点で調べた値）。

| 項目 | 費用 | 備考 |
| --- | --- | --- |
| Apple Developer Program | 年 99 ドル | 毎年かかる。iOS の実機に入れるだけでも要る |
| Google Play Console | 初回 25 ドル | 1 回だけ |
| EAS（Expo のビルドと配信） | 無料の枠で足りる | ビルドは月に iOS 15 回・Android 15 回、OTA の更新は月 1,000 人まで |
| AWS | ほぼ増えない | API はそのまま。使われた分だけ |

- Google Play は、個人のアカウントで本番に出す前に、12 人以上のテスターで 14 日続けてクローズドテストを行う必要がある
- どちらのストアも、プライバシーポリシーの URL が要る
- App Store は、アプリの中でアカウントを作れるなら、アプリの中から削除もできることを求める（App Store Review Guidelines 5.1.1(v)）。いまは利用者そのものを消す機能がない

## 結果

### 良い影響

- 認証の経路は 1 つのまま。バックエンドは、受け付ける `client_id` が 1 つ増えるだけ
- web で登録したパスキーを、アプリでもそのまま使える
- 解説の規則（生の HTML を通さない、`figure:` だけ）を、web と同じパーサで守れる
- 費用は増えない

### 悪い影響・受け入れるリスク

- **トークンが端末に置かれる。** web ではトークンをブラウザに渡さなかった（ADR-0016）。
  端末を奪われたうえでロックを破られると、リフレッシュトークンの期限（30 日）まで使える
- **`aws.cognito.signin.user.admin` のスコープを持つトークンを、利用者が手にする。** 自分の属性を書き換えられる。
  ADR-0016 では、トークンがブラウザに渡らないので書き換えの経路がない、としていた。メールアドレスは確認してからでないと替わらない設定（`attributes_require_verification_before_update`）で、
  バックエンドは確認済みのメールアドレスしか使わない。ほかの属性は使っていない
- ログインのたびに、ブラウザの画面が一度開く
- ネイティブの部分は Expo に任せるので、理解は深まらない
- iOS の実機では試せない（Apple Developer Program が要る）

### 緩和策

- トークンは OS の安全な置き場所にだけ置き、ログに出さない
- ログアウトでリフレッシュトークンを失効させる
- 利用者が書き換えられる属性を、バックエンドの判断に使わない。使うときは、この ADR を見直す

## 検証事項

- Expo の managed で、pnpm の monorepo（`apps/mobile`）が組めるか。Metro がワークスペースの依存を解決できるか
- Cognito が、カスタムスキーム（`quizapp://`）と `exp://` の戻り先を受け付けるか
- システムのブラウザの画面で、web で登録したパスキーが使えるか（iOS のシミュレータと Android の実機）
- 図のプレビューの API のリダイレクトを、React Native の画像の部品がたどれるか。たどれなければ、署名付き URL を返す API を足す
